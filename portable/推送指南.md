# 推送指南：外壳代码放到 GitHub，Actions 自动出包

## 现状与前提

- **上游** `https://github.com/deepseek-ai/deepseek-harness`：DeepSeek 官方维护，MIT，**版本更新只认这里**（发 `dsh-v*` tag，同时把 `@deepseek-ai/dsh` 发到 npm）。你只有读权限，没有写权限。
- **本机源码副本**：工作区里的 `deepseek-harness-master\`，是官方仓的快照（`@deepseek-ai/dsh-root` 0.2.2-alpha.3，没有 `.git`）。只用来取原始图标、查实现细节，不参与构建，也不往仓库里放。
- **fork** `lentll/deepseek-harness`：从官方仓 fork，现有 `master`（上游快照）和 `portable`（外壳）两个分支。它的作用只是**提供 Actions 和存放外壳代码**，不承担源码同步。
- 本机到 GitHub 实测下载速度约 **33 KB/s**，上游仓库 353 MB —— 完整克隆要 3 小时，不可行。所以这里用**独立根分支**：`portable` 不含上游代码，只放外壳源码（约 200 KB）和 workflow，推送与 CI 都很快。

```
lentll/deepseek-harness
├─ master      上游快照（fork 创建时的官方代码，只读参考，不参与出包）
└─ portable    独立根分支：portable/ + .github/workflows/portable-build.yml
```

## 已经替你准备好的内容

本机的 `dsh-portable-repo\` 目录就是要推的东西：

| 路径 | 内容 |
|---|---|
| `portable/` | Electron 外壳源码、构建/更新脚本、签名脚本、README、推送指南 |
| `.github/workflows/portable-build.yml` | 出包 workflow |
| `推送更新.cmd` | 本机辅助脚本（已 gitignore，不进仓库） |

**仓库里没有任何密钥，这点有三层保证**

1. **从没提交过**：全历史（9 个提交）扫过，没有 `.env`、`.credentials.yaml`、`*.pfx`、`*.pem`、`*.key` 这类文件被加入过，也没有 `data/` 路径进过历史；当前树里 `sk-` 只出现在正则和 `sk-xxxx` 占位示例中。
2. **提交不进去**：`.gitignore` 排除了 `.env`、`.env.*`、`.credentials.yaml`、`credentials.json`、`.git-credentials`、`*.pfx`、`*.p12`、`*.pem`、`*.key`、`data/`（`.env.example` 例外保留）。
3. **进不去包也发不出去**：workflow 有两道守卫——构建前扫仓库源码（`scripts/check-secrets.mjs`），构建后扫 `out\` 产物；任一命中即中断，报告只给文件名和行号，不回显密文。`data/` 另有 `7z -x!data\*` 排除，并在打包后回读压缩包确认没有 `data\`。

签名的证书和密码走 **Actions Secrets**（加密存储，只有工作流能读），仓库里只有 `secrets.SIGNING_PFX_BASE64` 这样的**引用**，没有值。

## 只有手动触发

两份 workflow（`portable` 上的 `portable-build.yml`、`master` 上的 `build-portable.yml`）都**只保留 `workflow_dispatch`**：没有 `schedule`，也没有 `push`。所以同步上游、改外壳、往 `portable` 提交，都不会自己开跑；要出包就去 Actions 点 **Run workflow**。

这么设的原因：一次构建要 8–12 分钟、下载 1.3 GB 依赖，自动跑容易在你没准备时占掉 Actions 额度，还可能覆盖已经发布出去的 Release（有人正在下载）。

要出包时的两条路：

**A. 日常用 master 那份（推荐）**
Actions → **Build portable (master)** → Run workflow，`version` 留空即可。默认分支就是 master，按钮一直在，和你在主仓库更新代码是同一个地方。

**B. portable 那份当备用**
Actions → **Build portable package** → Run workflow。内容与 A 的差别只是「版本从哪来」：B 只认上游最新 `dsh-v*`，A 会拿 master 的 `package.json` 和上游比大小。

如果你后来想恢复自动跑，把 `on:` 下加回 `schedule` / `push` 段即可（`master` 默认为分支时 `schedule` 才生效）。

## Actions 开关与签名 secret

1. Settings → Actions → General → **Allow all actions and reusable workflows** → Save
2. Settings → Secrets and variables → Actions 下的两个 secret：**已配置**（2026-11-05 通过 REST API 上传，`/actions/secrets` 回读 `total=2`）

| 名称 | 内容来源 |
|---|---|
| `SIGNING_PFX_BASE64` | `F:\WorkBuddyData\workspace\dsh-signing\portable-signing.pfx.base64.txt`（3680 字符，单行） |
| `SIGNING_PFX_PASSWORD` | `F:\WorkBuddyData\workspace\dsh-signing\password.txt`（24 字符） |

上传时用的是 libsodium `crypto_box_seal`（PyNaCl 的 `SealedBox`）对仓库公钥加密后再 PUT，明文没经过任何第三方；本地脚本 `F:\WorkBuddyData\workspace\dsh-signing\seal-secrets.py`，可重跑（公钥换了就要重跑）。

secret 的**值读不回来**（GitHub 单向存储），所以只能靠跑一次构建、看日志里「签名」那行是「已签名」来确认。不配也能出包，产物只是没有签名。**这两个值不要贴进任何仓库文件**，只能放 Secrets。

## workflow 行为

| 触发 | 行为 |
|---|---|
| 手动 Run workflow | **唯一的触发方式**。可指定版本号；勾 `force` 强制重建同名 Release |
| master 的 Run（`build-portable.yml`） | 版本取「master `package.json`」与「上游最新 `dsh-v*`」中较大的那个，没发到 npm 就回退另一个 |
| portable 的 Run（`portable-build.yml`） | 版本只认上游最新 `dsh-v*` release tag |

版本映射：GitHub tag `dsh-v0.2.2-rc.1` → npm `0.2.2-rc.1`。tag 打了但 npm 还没发布时，任务会 warning 后跳过，等下一次。

产物：Release `portable-v<版本>` + `DeepSeek-Harness-portable-<版本>.7z`（约 700 MB–1 GB，**不含 data**，所以不含 API Key）。

## 上游更新怎么进来

官方仓发版后**不需要任何手动同步**：官方发 `dsh-v*` tag → 同步发 `@deepseek-ai/dsh` 到 npm → CI 下一次跑（或手动 Run）就装上这个版本，`portable/` 里的外壳代码一行都不用改。fork 的 `master` 落后多少都不影响。

只有一种情况要看源码：外壳需要跟着上游改（比如新增的 preload、改了启动参数）。这时把那版官方源码下一份快照到工作区（`deepseek-harness-master\`），对照着改外壳即可——不要在 `portable` 里 merge 上游代码，那是独立根分支，merge 需要 `--allow-unrelated-histories`，会把 353 MB 历史一并拉进来。

## 常见失败

| 现象 | 原因 / 处理 |
|---|---|
| push 报 403 | fork 不是你的账号，或登录的是另一个账号 |
| Actions 里看不到 workflow | Actions 没开启；或文件不在默认分支上（master 那份才能直接在列表里看到） |
| push 了但没开始构建 | 预期行为：两份 workflow 都只有 `workflow_dispatch`，必须手动 Run |
| `npm 上还没有 x.y.z` | 上游打了 tag 但 npm 未发布，等下一次 |
| `credential files found in the build output` | 守卫生效：构建输出目录里混进了凭据文件，检查输出目录的 `data\` 是不是被误拷贝 |
| 产物被 SmartScreen 拦 | 自签名证书的预期行为；要彻底消除需付费 OV/EV 证书 |
